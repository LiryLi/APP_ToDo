# Windows 钉子窗口原型（R11 钉子模式）

桌面ToDo 项目的电脑端「钉子窗口」交互原型，用 **PowerShell + WPF + Win32 API** 实现，零依赖、无需安装任何运行时（系统自带 PowerShell 即可运行）。

## 怎么运行

- **双击 `启动钉子窗口.cmd`**（推荐）
- 或命令行：
  ```
  powershell -NoProfile -ExecutionPolicy Bypass -File .\pin_window_prototype.ps1
  ```

数据保存在同目录 `todos.json`，首次运行自动生成示例待办。

## 操作说明

| 操作 | 方式 |
|---|---|
| 添加待办 | 普通模式下输入文字 → 回车 / 点「添加」 |
| 勾选完成 / 删除 | 点清单行的勾选框 / 右侧 × |
| **钉住** | 点「📌 钉住」按钮，或热键 **Ctrl+Alt+P** |
| 取消钉住 | 热键 **Ctrl+Alt+P** |
| **双击折叠 / 展开** | 钉住态下，鼠标移入窗口后**立即双击**（见下方时序说明） |
| 展开 / 折叠（键盘） | 热键 **Ctrl+Alt+E** |
| 关闭 | 普通模式点 ✕ 或 Alt+F4 |

## 钉住后的交互时序（重要）

悬停透明 + 点击穿透 + 双击折叠三者在物理上互相冲突（穿透开启后点击必然落到下层），
因此采用「缓冲期」设计：

```
鼠标移入钉住的窗口
   │
   ├─ 立即：整体变为 50% 透明（视觉反馈）
   │
   ├─ 移入后 0.3 秒内：窗口仍可点击 → 此期间双击 = 折叠/展开
   │                    （单击后还会再保留 0.5 秒等待第二击）
   │
   └─ 悬停满 0.3 秒：进入点击穿透态 → 点击落到下方桌面/窗口
                     （想再双击：鼠标移出再移入）
```

- 穿透态下点击下层软件可以正常交互（这正是穿透的目的）；
- 想折叠/展开但已进入穿透态：把鼠标移出窗口再移入，随即双击；
- 或直接用热键 Ctrl+Alt+E。

## 折叠条内容

折叠成一行时**只显示最上面一条未完成的待办**（文字过长自动省略），全部完成时显示「📌 暂无待办」。

## 设计说明（可迁移到正式客户端）

核心 Win32 / WPF 技术点：

- 置顶：`HWND_TOPMOST`（WPF `Window.Topmost`）
- 悬停穿透：`WS_EX_LAYERED | WS_EX_TRANSPARENT` 扩展样式 + `Window.Opacity = 0.5`
- 穿透态感知：穿透开启后窗口收不到任何鼠标事件，只能用 **40ms 光标轮询**（`GetCursorPos` 与 `GetWindowRect` 比较）判断光标进入/离开
- 双击折叠：监听 `PreviewMouseLeftButtonDown`（隧道阶段）——**WPF 的 ScrollViewer 会把清单区域的冒泡点击标记为已处理**，普通 `MouseLeftButtonDown` 在窗口级收不到，必须用 Preview；双击用 450ms 手动计时判定
- 热键：`GetAsyncKeyState` 轮询（正式版建议换成 `RegisterHotKey`）

## 自检结果

`pin_window_prototype.ps1 -Selftest` 覆盖 20 项断言：置顶、无边框、只读、折叠、折叠条内容、悬停透明度、穿透样式位、取消钉住恢复、**真实光标端到端悬停/穿透**（自动移动鼠标）、**模拟双击折叠**、数据持久化。

- PowerShell 7.6.4（pwsh）：**20/20 PASS**
- Windows PowerShell 5.1：**20/20 PASS**

## 排障

- 悬停透明/穿透**只在钉住态生效**：普通模式下悬停无任何效果，请先点「📌 钉住」或 Ctrl+Alt+P。
- 若行为异常，查看同目录 `tick_error.log`（轮询循环异常会自动记录）。

## 已知限制（原型范围外）

- 单实例、无跨端同步（对应正式版 Pipeline 4）
- 无分级提醒 / 远程目标回拉（R9、R10 属于提醒引擎，另行原型）
- 钉住态窗口位置固定（穿透使拖动不可行）；位置在普通模式下调整后钉住
- 热键为全局轮询实现，与其他软件的 Ctrl+Alt+P/E 可能冲突
- 折叠条与清单为简化样式，正式版由 UI 设计稿承接
