# Windows 置顶窗口原型（R11 置顶模式）

桌面ToDo 项目的电脑端「置顶窗口」交互原型，用 **PowerShell + WPF + Win32 API** 实现，零依赖、无需安装任何运行时（系统自带 PowerShell 即可运行）。

## 怎么运行

- **双击 `启动置顶窗口.cmd`**（推荐；本机 pwsh 不在 PATH 时会自动回退到 Windows PowerShell 5.1，两版本均已通过全部自检）
- 或命令行：
  ```
  powershell -NoProfile -ExecutionPolicy Bypass -File .\pin_window_prototype.ps1
  ```

数据保存在同目录 `todos.json`，首次运行自动生成示例待办。

## 操作说明

| 操作 | 方式 |
|---|---|
| 添加待办 | 普通模式下输入文字 → 回车 / 点「添加」 |
| 勾选完成 / 删除 | 点清单行的勾选框 / 右侧 × |
| 移动窗口 | 普通模式下按住标题栏空白处拖动（窗口为无边框自绘） |
| **置顶** | 点「📌 置顶」按钮，或热键 **Ctrl+Alt+P** |
| 取消置顶 | 点悬浮的「📌 取消置顶」**独立按钮层**（置顶态始终不透明、可点击），或热键 **Ctrl+Alt+P** |
| **双击折叠 / 展开** | 置顶态下，鼠标移入窗口后**立即双击**（见下方时序说明） |
| 展开 / 折叠（键盘） | 热键 **Ctrl+Alt+E** |
| 关闭 | 点 ✕ 或 Alt+F4 |

## 置顶后的交互时序（重要）

悬停透明 + 点击穿透 + 双击折叠三者在物理上互相冲突（穿透开启后点击必然落到下层），
因此采用「缓冲期」设计：

```
鼠标移入置顶的窗口
   │
   ├─ 立即：整体变为 20% 透明（隐约看到下层窗口内容）
   │
   ├─ 移入后 1 秒内：窗口仍可点击 → 此期间双击 = 折叠/展开
   │                  （两次点击间隔最长 1 秒；单击后还会再保留 1 秒等待第二击）
   │
   └─ 悬停满 1 秒：进入点击穿透态 → 点击穿过本窗口，与下层软件正常交互
                     （想再双击：鼠标移出再移入）
```

- 穿透态下点击下层软件可以正常交互（这正是穿透的目的）；
- 想折叠/展开但已进入穿透态：把鼠标移出窗口再移入，随即双击；
- 或直接用热键 Ctrl+Alt+E。

## 独立置顶按钮层

置顶后，主窗口顶边右上方会出现一个悬浮的「📌 取消置顶」按钮。它是**独立的第二个窗口**（独立 HWND），因此：

- **永不变透明**：主窗口悬停变 20% 时，它保持 100% 不透明；
- **永不穿透**：主窗口进入点击穿透后，它仍然可以正常点击；
- 点击即取消置顶，恢复普通可编辑窗口；取消后它自动隐藏，主窗口内的置顶按钮恢复；
- 折叠态同样可用。鼠标移到它上面时主窗口会恢复不透明（光标已离开主窗口矩形），
  主窗口内的按钮在置顶态隐藏，避免重复。

## 折叠条内容

折叠成一行时**标题栏同步隐藏**，整行只显示最上面一条未完成的待办（文字过长自动省略），全部完成时显示「📌 暂无待办」。右侧保留热键提示。

## 设计说明（可迁移到正式客户端）

核心 Win32 / WPF 技术点，含本次 debug 定位出的两个关键坑：

- **真正的点击穿透 = 真分层窗口 + `WS_EX_TRANSPARENT`**：
  窗口以 `AllowsTransparency="True"` + `WindowStyle="None"` 创建，WPF 通过
  UpdateLayeredWindow 渲染，本身就是分层窗口，`Window.Opacity` 原生控制整体
  alpha（悬停 0.2）；再叠加 `WS_EX_TRANSPARENT` 扩展样式，点击才真正穿过窗口。
- **坑 1：`WS_EX_TRANSPARENT` 单独存在不是点击穿透**，它只是绘制顺序标记，
  必须与 `WS_EX_LAYERED` 组合才有穿透语义。
- **坑 2：普通 WPF 窗口混用 `Opacity` 与手动 `SetWindowLong(WS_EX_LAYERED)` 会互相打架**——
  WPF 管理 Opacity 时会重写扩展样式，把手动加的 LAYERED 冲掉，穿透因此失效。
  对 DirectX 渲染的普通窗口外部强加 LAYERED 也不产生真分层。
  正确做法就是让 WPF 窗口以 AllowsTransparency 原生分层。
- 样式变更后调用 `SetWindowPos(SWP_FRAMECHANGED)` 使其生效。
- 独立置顶按钮层：第二个 AllowsTransparency 窗口，`Topmost` 且每 40ms 用
  `SetWindowPos(主窗口句柄)` 固定在主窗口之上（不激活不抢焦点），
  位置跟随主窗口；主窗口的透明/穿透状态机完全不作用于它。
- 置顶：`Window.Topmost`；穿透态感知：穿透后窗口收不到鼠标事件，用 40ms
  光标轮询（`GetCursorPos` 与 `GetWindowRect` 比较）判断进入/离开。
- 双击折叠：监听 `PreviewMouseLeftButtonDown`（隧道阶段）——**WPF 的
  ScrollViewer 会把清单区域的冒泡点击标记为已处理**，窗口级普通
  `MouseLeftButtonDown` 收不到；双击用 1000ms 手动计时判定。
- 热键：`GetAsyncKeyState` 轮询（正式版建议换成 `RegisterHotKey`）。
- 脚本启动时 `SetProcessDPIAware`，保证 DIP / 物理像素 / 光标坐标一致。

## 自检结果

`pin_window_prototype.ps1 -Selftest` 覆盖 27 项断言，其中包含**真实穿透验收**：
在下层放置计数窗口并注入真实鼠标点击，断言「下层窗口收到点击、本窗口未截获」，
以及**真实点击独立置顶按钮取消置顶**，而不是只检查样式位。

- PowerShell 7.6.4（pwsh）：**27/27 PASS**
- Windows PowerShell 5.1：**27/27 PASS**

自检工程化措施：

- 自检窗口使用独立测试位置，避免与正在运行的实例重叠；
- 自检读写独立临时数据文件（`%TEMP%\pin_selftest_todos.json`），**绝不触碰用户的 todos.json**；
- 自检通过 `PrintWindow` 抓取窗口本体截图（`%TEMP%\pin_collapsed_pw.png` 等）供人工核对；
- `-ClickTest` 开关可单独跑「下层受害窗口」穿透实验，输出双方各自收到的点击数。

## 排障

- 悬停透明/穿透**只在置顶态生效**：普通模式下悬停无任何效果，请先点「📌 置顶」或 Ctrl+Alt+P。
- 若行为异常，查看同目录 `tick_error.log`（轮询循环异常会自动记录）。

## 已知限制（原型范围外）

- 单实例、无跨端同步（对应正式版 Pipeline 4）
- 无分级提醒 / 远程目标回拉（R9、R10 属于提醒引擎，另行原型）
- 窗口永久无边框（AllowsTransparency 需要）：普通模式固定尺寸、用标题栏拖动移动；
  置顶态位置固定（穿透使拖动不可行），位置在普通模式下调整后置顶
- 热键为全局轮询实现，与其他软件的 Ctrl+Alt+P/E 可能冲突
- 折叠条与清单为简化样式，正式版由 UI 设计稿承接
