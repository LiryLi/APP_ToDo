## 二、验收前置条件（缺一不可）

### 1. 一台设备（二选一）

- **真机**（推荐，最接近真实场景）：Android 8.0（API 26）及以上，USB 调试已打开，`adb devices` 能看到设备。
- **模拟器**：原生 Android 35 镜像。模拟器验证的是 Framework 行为，厂商锁屏定制要另测。

### 2. 设备必须先设好锁屏密码

这一步容易被跳过，但它是“免解锁”能否成立的前提：
**若锁屏本身没有密码，就不存在“是否触发认证”**，验收结论无效。
请先在系统设置里设置 PIN / 图案 / 密码，并确认按电源键锁屏后，点亮屏幕会出现需要认证的锁屏界面。

### 3. 工具

`adb` 位于 `C:\Users\admin\AppData\Local\T01AndroidToolchain\sdk\platform-tools\adb.exe`。
下文命令用 `adb` 指代该可执行文件。

## 三、安装与准备

```powershell
$adb = 'C:\Users\admin\AppData\Local\T01AndroidToolchain\sdk\platform-tools\adb.exe'
$apk = 'E:\APP_桌面TODO\project\T0.1_Android锁屏速记原型\dist\locknote-t01-demo.apk'

& $adb devices -l
& $adb install -r $apk
```

安装成功后，打开应用「锁屏速记」，界面会显示 **「渠道锁屏可见性：PUBLIC」**，确认这一行是 PUBLIC。

然后按顺序做完三件事：

1. **授予通知权限**（Android 13+）：点「发送速记通知」，系统弹出通知权限申请时选择允许。
2. **锁屏显示全部内容**：系统设置 → 通知 → 锁屏通知 → 选择「显示所有通知内容 / 显示完整内容」。
3. **厂商额外开关**（仅国产 ROM）：设置里搜索「锁屏通知」，确认已开启「锁屏通知可操作」或「直接回复 / 快捷回复」。小米、华为、OPPO、vivo 等机型此开关位置不同，部分机型默认关闭。

> 已知边界：若厂商系统禁止锁屏通知内输入，则该机型无法通过本项验收。这属于厂商限制，**不能算作通过**，应换原生 Android 设备（Pixel / 模拟器）验收。这条是任务边界，不是实现缺陷。

## 四、执行锁屏速记（关键在“不解锁”）

1. 在应用中再点一次 **「发送速记通知」**，通知栏出现「锁屏速记」通知。
2. 按电源键**锁屏**，让屏幕熄灭后再点亮，停在锁屏界面。
3. 在锁屏界面**下拉通知栏**，展开「锁屏速记」通知。
4. 点通知上的 **「保存速记」** 按钮，出现输入框（标签「输入速记」）。
5. 输入一段文字，例如 `锁屏验收 001 买牛奶`，点发送/保存。
6. 观察通知标题变为 **「已保存 #1 · 可继续速记」**，正文回显刚输入的文字。
7. 不输入密码，直接按电源键熄屏，再点亮，确认仍在锁屏界面（没有因刚才的操作被要求认证）。

**全过程中不允许出现的行为**（出现任意一条即判定失败）：
- 弹出密码 / PIN / 图案 / 指纹 / 人脸验证界面
- 跳转到「锁屏速记」应用界面
- 通知内容被折叠成「内容已隐藏」

## 五、判定标准（逐条打勾才算通过）

| # | 判定项 | 通过标准 |
|---|---|---|
| 1 | 锁屏可见 | 锁屏界面通知栏能看到「锁屏速记」，内容未被隐藏 |
| 2 | 内嵌输入 | 锁屏通知上有「保存速记」按钮，点击后可直接输入，无跳转 |
| 3 | 保存回显 | 通知变为「已保存 #N · 可继续速记」，正文回显输入文本 |
| 4 | 落库 | SQLite `notes` 表出现该记录，`source = lockscreen_remote_input` |
| 5 | 免认证 | 全程无密码/生物认证界面，无跳转应用 |
| 6 | 可复现 | 重复步骤 3–6 能连续保存第 2、3 条，编号递增 |
| 7 | 录屏 | 有覆盖步骤 2–7 的完整录屏 |

## 六、录屏

录屏需要在**锁屏状态下**开始：

```powershell
$adb = 'C:\Users\admin\AppData\Local\T01AndroidToolchain\sdk\platform-tools\adb.exe'
$out = 'E:\APP_桌面TODO\project\T0.1_Android锁屏速记原型\docs\lockscreen-demo.mp4'

# 先熄屏再点亮，停在锁屏界面
& $adb shell input keyevent KEYCODE_POWER
Start-Sleep -Seconds 1
& $adb shell input keyevent KEYCODE_POWER

# 开始录屏（最长 180 秒，够走完整流程）
& $adb shell screenrecord --time-limit 180 --size 1080x1920 --bit-rate 6000000 /sdcard/lockscreen-demo.mp4

# 走完第四节步骤后再停止，随后取回文件
& $adb pull /sdcard/lockscreen-demo.mp4 $out
& $adb shell rm /sdcard/lockscreen-demo.mp4
```

录屏要求：能看清「锁屏界面 → 下拉通知 → 点击保存速记 → 输入框 → 输入文字 → 变为已保存 #N」的完整链路，且画面中不出现任何密码输入框。

## 七、失败排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 通知完全不出现 | 通知权限未授予，或渠道被关闭 | 系统设置 → 应用 → 锁屏速记 → 通知，开启；或用应用内「打开通知渠道设置」 |
| 锁屏只显示「内容已隐藏」 | 系统锁屏通知策略为隐藏敏感内容 | 锁屏通知改为「显示所有通知内容」 |
| 展开通知后没有输入框 | 厂商禁止锁屏通知内输入 | 开启「锁屏通知可操作/直接回复」；仍不行则换原生 Android 验收 |
| 点「保存速记」直接跳进应用 | 厂商把内嵌回复改写成打开应用 | 同上，属厂商行为，需换设备验收 |
| 通知没有变成「已保存 #N」 | 广播未送达或数据库写入异常 | `adb logcat -s LockNoteReceiver` 查看日志 |
| 编号一直是 #1 | 数据库每次被清空（重装应用） | 属正常，卸载重装会清库 |
| `run-as` 报 not debuggable | 装的是 release 包 | 使用本项目 `dist` 下的 demo 包 |
