# T0.2 飞书同步助手（桌面TODO · 手机采集通道）

## 这是什么

手机飞书里给机器人发一句话 → 2 秒内出现在桌面置顶待办窗口；每天早上把未完成清单推回手机。

选飞书的原因：个人开发者唯一"零服务器、零费用、采集+提醒双向"的通道。微信个人号只能收消息不能发消息，且收消息还要架公网服务器。通道在架构上是可插拔的，将来要覆盖纯微信用户，可以再加"订阅号采集"模块（提醒方向微信对个人开发者无解）。

## 文件

- `daemon.py` 守护进程：长连接收消息 → 追加 todos.json → 回执"已加入待办 #N"；每天 digest_time 推送未完成清单
- `config.json` 配置：app_id、app_secret、todos 路径、每日清单时间
- `run.ps1` 启动/停止（后台运行，日志 daemon.log）
- `说明.md` 本文档

## 一次性配置（约 10 分钟，只做一次）

1. 浏览器打开 https://open.feishu.cn → 开发者后台 → **创建企业自建应用**，名字随意（如"桌面TODO助手"）
2. 应用能力 → 添加**机器人**
3. 权限管理 → 开通：
   - 读取用户发给机器人的单聊消息（im.message.receive_v1 相关）
   - 以应用身份发消息（im:message:send_as_bot）
4. 事件与回调 → 订阅方式选**使用长连接接收事件** → 添加事件**接收消息 im.message.receive_v1**
5. 版本管理与发布 → 创建版本并发布（可用范围给本租户自己即可）
6. 凭证与基础信息 → 复制 **App ID** 和 **App Secret**，填进 `config.json`
7. 运行 `run.ps1` → 守护进程后台启动
8. 手机飞书 → 搜索你的机器人名字 → 发一句话，例如「买牛奶」

## 验收清单

1. 手机发消息后 5 秒内，机器人回复"已加入待办 #N"
2. 同一时间，`todos.json` 里出现该条目（done=false、tag=远程）
3. 置顶窗口 2 秒内自动显示新条目，无需重启窗口（补丁后的自动刷新）
4. 每日 digest_time，手机收到未完成清单；全部完成则不发
5. 在窗口里勾选完成与守护进程写入互不覆盖（保存前合并保护）
6. 守护进程停止不影响置顶窗口；重新启动后通道自动恢复
7. 电脑关机期间手机发的消息不会入库（通道依赖桌面在线，见已知限制）

## 已知限制

- 通道依赖桌面在线：电脑关机时手机发的消息进不来（飞书侧会重试一段时间，但最终会丢）
- 仅支持文字消息，图片/语音会收到提示
- todos.json 没有唯一 ID，合并保护按"文本相同"识别同一条目
- Python 依赖本机已装的 Python 3（run.ps1 会自动装 lark-oapi）
